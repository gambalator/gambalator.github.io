# Установка и запуск Gambalator в Windows

Это руководство предназначено для первого запуска Gambalator на Windows 10 или
Windows 11. При стандартном запуске приложение работает локально через один
Python-сервер: он открывается только на компьютере пользователя, отдаёт веб-интерфейс
и синхронизируется с DonationAlerts. Дополнительный вариант совместного запуска с
Only_DA-Goal описан в разделе 8.

## 1. Установить mise

`mise` устанавливает подходящие версии Node.js, npm, Python и `uv`, поэтому отдельно
устанавливать эти программы не нужно.

1. Откройте меню «Пуск».
2. Найдите и запустите **PowerShell** или **Терминал**.
3. Выполните команду:

   ```powershell
   winget install --exact --id jdx.mise
   ```

4. Закройте окно терминала и откройте его снова, чтобы Windows обновила `PATH`.
5. Проверьте установку:

   ```powershell
   mise --version
   ```

   Команда должна вывести номер версии `mise`.

Официальные варианты установки перечислены в
[документации mise](https://mise.jdx.dev/installing-mise.html). Если `winget` на
компьютере недоступен, там же можно выбрать установку через Scoop или вручную.

## 2. Скачать и распаковать проект

1. Скачайте актуальный архив проекта.
2. Нажмите на архив правой кнопкой мыши и выберите **Извлечь всё**.
3. Поместите распакованную папку в постоянное место, например:

   ```text
   C:\Gambalator
   ```

Не запускайте проект прямо из ZIP-архива. В корне распакованной папки должны
находиться файлы `mise.toml` и `start-gambalator.cmd`.

## 3. Открыть терминал в папке проекта

Откройте папку Gambalator в Проводнике, нажмите правой кнопкой мыши по свободному
месту и выберите **Открыть в терминале**.

Или перейдите в неё из PowerShell вручную:

```powershell
cd "C:\Gambalator"
```

Если папка находится в другом месте, укажите её настоящий путь.

## 4. Подготовить проект к первому запуску

Выполняйте команды из корневой папки Gambalator:

```powershell
mise trust
mise install
mise run setup
mise run backend-setup
```

Что делают эти команды:

- `mise trust` разрешает использовать конфигурацию `mise.toml` из этой папки;
- `mise install` устанавливает версии Node.js, npm, Python и `uv`, указанные проектом;
- `mise run setup` устанавливает зависимости веб-интерфейса;
- `mise run backend-setup` создаёт окружение Python и устанавливает зависимости
  локального сервера.

Для этих операций нужен интернет. Установка может занять несколько минут. Сообщения
о скачивании пакетов при первом запуске нормальны.

## 5. Запустить Gambalator

В том же терминале выполните:

```powershell
.\start-gambalator.cmd
```

После появления сообщения о запуске откройте в браузере:

```text
http://127.0.0.1:5741
```

Окно терминала должно оставаться открытым всё время работы с Gambalator. Чтобы
остановить приложение, вернитесь в терминал и нажмите `Ctrl+C`, либо закройте окно.

При стандартном запуске без Only_DA-Goal работает только один сервер — Python-сервер
на порту `5741`. Перед его запуском команда автоматически собирает React-интерфейс в
статические файлы, после чего Python обслуживает и страницу, и локальное API. Отдельно
запускать `mise run dev` не нужно.

После успешной первичной установки приложение можно запускать двойным щелчком по
`start-gambalator.cmd`. Запуск из терминала удобнее, если потребуется прочитать
сообщение об ошибке.

## 6. Первое подключение DonationAlerts

Для автоматического импорта нужен зарегистрированный клиент DonationAlerts.

1. Запустите Gambalator и откройте `http://127.0.0.1:5741`.
2. Разверните блок **DonationAlerts**.
3. Скопируйте показанный в нём Redirect URI. При стандартном запуске это:

   ```text
   http://127.0.0.1:5741/api/oauth/callback
   ```

4. Откройте страницу приложений DonationAlerts по ссылке из интерфейса.
5. Создайте приложение. Его название может быть любым понятным названием, например
   `Gambalator`.
6. Укажите скопированный Redirect URI без изменений.
7. Сохраните приложение и скопируйте выданные **App ID** и **API Key**.
8. Введите их в Gambalator и нажмите **ПОДКЛЮЧИТЬ DONATIONALERTS**.
9. На открывшейся странице DonationAlerts подтвердите доступ к нужному аккаунту.
10. После возврата в Gambalator убедитесь, что показаны зелёные состояния
    **Связь есть**, **Синхронизация активна** и статус **Подключено**.

При самом первом подключении backend сохраняет текущий последний донат как начальную
точку и по умолчанию не загружает всю старую историю аккаунта. Для проверки отправьте
тестовый донат уже после успешного подключения. Новая запись обычно появляется в
активном списке в течение нескольких секунд.

Если нужны донаты, отправленные до первого подключения, используйте секцию
**Загрузка истории** в подключённом блоке DonationAlerts. Выберите дату и время,
нажмите **ЗАГРУЗИТЬ ИСТОРИЮ**, проверьте предварительный результат и подтвердите
добавление. Повторное расширение периода не создаёт дубликаты среди активных записей,
а впервые найденная история всегда добавляется как обычные донаты без Chat. Уже
рассчитанный или удалённый донат можно намеренно добавить целиком ещё раз. Старые
использованные строки и история победителей не удаляются, поэтому перед перерасчётом
очистите их вручную, если они больше не нужны.

App ID можно безопасно показать во frontend, но API Key, access token и refresh token
локальное API никогда не возвращает. В обычной конфигурации все данные авторизации
сохраняются в Windows Credential Manager. Если системное хранилище недоступно,
интерфейс предупредит, что используется локальный файл в каталоге данных Gambalator.

## 7. Последующие запуски

После первой настройки достаточно:

```powershell
cd "C:\Gambalator"
.\start-gambalator.cmd
```

Вводить App ID и API Key повторно не нужно. Если истёк только access token, backend
обновит его с помощью refresh token автоматически. Если DonationAlerts отклонил и
refresh token, интерфейс покажет **Требуется повторная авторизация**. В таком случае
нажмите **ПЕРЕПОДКЛЮЧИТЬ DONATIONALERTS**: сохранённые App ID и API Key будут
использованы повторно.

## 8. Совместный запуск с Only_DA-Goal (необязательно)

Only_DA-Goal можно использовать как OBS-виджет и единый launcher для обоих проектов.
Gambalator работает на порту `5741`, Only_DA-Goal — на порту `5000`, а общий
supervisor запускает и останавливает оба дерева процессов из одной консоли.

В синхронизированном режиме DonationAlerts подключается к Gambalator. Активная сумма,
цель, кнопки интерфейса, F6/F7 и OBS используют одно SQLite-состояние Gambalator.
Страница браузера не обязана оставаться открытой.

Готовый комплект файлов Only_DA-Goal находится в
`Gambalator\extras\only-da-goal`. Полная пошаговая подготовка — от расположения
папок и резервной копии до копирования файлов и первого запуска — вынесена в
[отдельную инструкцию](./ONLY_DA_GOAL_INSTALL_RU.md).

По умолчанию проекты располагаются рядом, а папка Gambalator называется
`Gambalator`:

```text
C:\StreamTools\
├── Gambalator\
└── Only_DA-Goal\
```

После подготовки запускайте `Only_DA-Goal\1.bat`. В консоли появятся адреса:

```text
OBS sync:   http://127.0.0.1:5000/donationObsOverlay
OBS legacy: http://127.0.0.1:5000/donationGoalRGG
Gambalator: http://127.0.0.1:5741/
```

Для OBS используйте синхронизированный адрес `/donationObsOverlay`. F6 рассчитывает
один полный гамбашар, F7 — все доступные полные гамбашары; исходные F20/F21/F22
сохраняют legacy-действия Only_DA-Goal. `Ctrl+C` или закрытие общей консоли
останавливает оба приложения.

Объяснение архитектуры, настройки изображений, горячих клавиш и диагностики находится
в [описании интеграции](./ONLY_DA_GOAL_COMPANION_RU.md).

## 9. Обновление проекта в новой папке

Если получена новая версия Gambalator:

1. Остановите старую копию приложения. Две копии нельзя одновременно запустить на
   одном порту `5741`.
2. Распакуйте новую версию в новую папку.
3. Откройте терминал в новой папке.
4. Выполните команды первичной подготовки:

   ```powershell
   mise trust
   mise install
   mise run setup
   mise run backend-setup
   ```

5. Запустите новую версию:

   ```powershell
   .\start-gambalator.cmd
   ```

Если используется совместный запуск с Only_DA-Goal, вместо шага 5 обновите комплект
по разделу 10 [отдельной инструкции](./ONLY_DA_GOAL_INSTALL_RU.md), а затем запускайте
`Only_DA-Goal\1.bat`.

На том же компьютере и под тем же пользователем новая папка продолжит использовать:

- авторизацию DonationAlerts из Windows Credential Manager;
- SQLite-базу, состояние калькулятора, последний обработанный ID DonationAlerts и
  режим Авто-Chat из `%LOCALAPPDATA%\Gambalator`.

Поэтому повторная авторизация обычно не требуется, а backend продолжает загрузку с
последней сохранённой позиции. Папки `node_modules`, `backend\.venv`, `dist` и кэш
зависят от конкретной копии проекта и создаются заново.

Браузер и его профиль больше не влияют на данные локального режима. Статическая
HTML-версия без backend по-прежнему использует отдельный `localStorage` браузера.

Старое состояние `localStorage` намеренно не переносится в SQLite автоматически.
При первом запуске этой версии локальный калькулятор начнёт с пустого списка и
настроек по умолчанию; ранее сохранённые данные статической версии не удаляются.

## 10. Где сохраняются данные

Основная база backend находится здесь:

```text
%LOCALAPPDATA%\Gambalator\gambalator.sqlite3
```

В ней находятся:

- последний полученный ID DonationAlerts;
- полученные донаты и их статусы;
- настройки, активные и использованные записи, их порядок и история победителей;
- очередь неподдерживаемых или ещё не обработанных донатов;
- режим **Авто-Chat для новых донатов**;
- самая ранняя успешно проверенная дата истории DonationAlerts;
- время последней успешной синхронизации.

Ручные донаты, настройки и результаты находятся в `calculator_state`. Записи из
DonationAlerts дополнительно хранятся в таблице `donations`, а курсоры — в
`sync_state`. Файл SQLite бинарный: для безопасного просмотра используйте DB Browser
for SQLite или `sqlite3`, предварительно остановив Gambalator. Перед ручным изменением
обязательно сделайте резервную копию `gambalator.sqlite3`.

Не удаляйте `%LOCALAPPDATA%\Gambalator`, если нужно сохранить рабочее состояние.
Обычное удаление старой папки с исходным кодом эти данные не удаляет. `localStorage`
используется только отдельной статической HTML-версией без backend.

## 11. Частые проблемы

### Команда `mise` не найдена

Закройте все окна PowerShell после установки `mise` и откройте новое. Затем выполните:

```powershell
mise --version
```

Если команда по-прежнему не найдена, повторите установку через `winget` и проверьте
рекомендации для Windows в официальной документации `mise`.

### Конфигурация проекта не доверена

Убедитесь, что терминал открыт в папке с `mise.toml`, и выполните:

```powershell
mise trust
```

### Страница не открывается

Проверьте, что окно с `start-gambalator.cmd` остаётся открытым и в нём нет ошибки.
Введите адрес вручную:

```text
http://127.0.0.1:5741
```

### Порт `5741` уже занят

Скорее всего, уже запущена старая или вторая копия Gambalator. Закройте её терминал и
повторите запуск новой версии.

### В интерфейсе написано «Локальный сервер недоступен»

Страница была открыта без работающего Python-сервера либо из standalone-файла.
Запустите `start-gambalator.cmd` и откройте именно `http://127.0.0.1:5741`.

### DonationAlerts не подключается

Проверьте следующее:

- Redirect URI в кабинете DonationAlerts полностью совпадает со значением в
  Gambalator;
- используются App ID и API Key одного и того же приложения;
- компьютер подключён к интернету;
- в блоке соединений есть зелёное состояние между веб-страницей и локальным
  сервером;
- дата и время Windows выставлены правильно.

### Ошибка `CredWrite` / `WinError 1783` при подключении DonationAlerts

Такая ошибка означает, что Windows Credential Manager не смог сохранить данные
авторизации. В автоматическом режиме Gambalator переключается на локальный файл
`%LOCALAPPDATA%\Gambalator\donationalerts-credentials.json`; интерфейс сообщает,
что это не защищённое системное хранилище.

Если вместо возврата в приложение появился экран ошибки, остановите сервер через
`Ctrl+C`, установите версию с исправлением обработки ошибок Credential Manager
и снова запустите `start-gambalator.cmd`. Откройте `http://127.0.0.1:5741` и
повторите подключение DonationAlerts кнопкой в приложении. Не обновляйте старую
страницу `/api/oauth/callback`: для повторной попытки нужна новая авторизация.

### После подключения старые донаты не появились

Это штатное поведение первого запуска: Gambalator начинает автоматический импорт с
текущей позиции, чтобы не принять всю историю DonationAlerts за новые донаты.
Разверните блок **DonationAlerts**, в секции **Загрузка истории** выберите начальную
дату и нажмите **ЗАГРУЗИТЬ ИСТОРИЮ**. После предварительного просмотра подтвердите
добавление. Впервые найденные исторические записи всегда добавляются без Chat.
Использованные строки не блокируют восстановление полного доната; прежние результаты
при этом остаются до отдельной очистки.

### `DonationAlerts request failed: ... Read timed out`

Backend не получил ответ `www.donationalerts.com` за 15 секунд. Обычно это временная
задержка DonationAlerts, нестабильное интернет-соединение, VPN/proxy, антивирусная
проверка HTTPS или блокировка домена. Gambalator не сдвигает курсор неуспешного
запроса и попробует снова при следующем цикле. Если сообщение повторяется длительное
время, проверьте открытие DonationAlerts в браузере, временно отключите VPN/proxy и
проверьте правила антивируса или брандмауэра. Не удаляйте SQLite и не переподключайте
OAuth из-за единичного тайм-аута.

### В консоли повторяется `GET /getDataGambalator ... 503`

Это не скрытое служебное сообщение, а признак того, что OBS-виджет Only_DA-Goal не
может получить состояние Gambalator. Успешные ответы `200` этого опроса специально не
печатаются, а ошибки `503` остаются видимыми. Проверьте, что backend Gambalator
запущен на порту `5741`, в консоли supervisor нет ошибки запуска и
`http://127.0.0.1:5741/api/overlay/state` открывается. Пока связь отсутствует, виджет
сохраняет последнее корректное значение.
