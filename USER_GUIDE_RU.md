# Руководство пользователя Gambalator

Gambalator собирает донаты в упорядоченную очередь, переводит их в рубли, делит на
гамбашары фиксированной суммы и выбирает победителя с учётом доната, который закрыл
каждый гамбашар. Интерфейс рассчитан на работу на компьютере и отображается на русском
языке.

## 1. Открытие приложения

Запустите локальное приложение и откройте:

```text
http://127.0.0.1:5741
```

В верхней части страницы показана краткая сводка:

- красная или зелёная кнопка состояния **DonationAlerts**;
- кнопка **Меню** для параметров расчёта.

Основные блоки страницы расположены в следующем порядке:

1. строка истории победителей, открывающая отдельное окно;
2. активные записи и кнопки расчёта.

История победителей и использованных записей объединена в одном окне над рабочей областью.
Параметры расчёта находятся в **Меню** в шапке.
Ручное добавление открывается кнопкой `+` справа от кнопок расчёта.

## 2. Подключение DonationAlerts

Кнопка **DonationAlerts** в шапке зелёная при исправной синхронизации и красная, если связи нет
или требуется действие. Нажатие открывает окно настройки со схемой:

```text
Веб-страница → Локальный сервер → DonationAlerts
```

Каждое соединение проверяется отдельно:

- **Связь есть** означает, что страница получает ответы от локального Python-сервера;
- **Синхронизация активна** означает, что backend подключён к DonationAlerts и
  опрашивает его API;
- зелёные подписи и точки обозначают исправное соединение;
- красная подпись сообщает об ошибке или необходимости авторизации.

### Первое подключение

1. Нажмите кнопку **DonationAlerts** в шапке.
2. Зарегистрируйте приложение в DonationAlerts с Redirect URI, показанным на странице.
3. Введите его **App ID** и **API Key**.
4. Нажмите **ПОДКЛЮЧИТЬ DONATIONALERTS**.
5. Подтвердите доступ на сайте DonationAlerts.
6. После возврата проверьте зелёные состояния соединений.

После подключения видны счётчик **Ожидают импорта**, время последней синхронизации по
Москве и тип хранилища авторизации. Поддерживаемые записи backend обычно переносит в
калькулятор сразу; в счётчике могут задерживаться неподдерживаемые валюты или записи,
обработка которых ещё не завершилась. Сообщение об успешном подключении скрывается
автоматически через пять секунд.

При первом подключении приложение создаёт начальную точку на текущем последнем донате
и не импортирует всю старую историю аккаунта. Донаты, отправленные после подключения,
появляются в активном списке через несколько секунд. Их получает и добавляет backend,
поэтому страница Gambalator может быть закрыта. После повторного открытия она прочитает
актуальное состояние из SQLite.

### Автоматический импорт

Backend проверяет DonationAlerts каждые пять секунд и сохраняет новые донаты в
локальной SQLite-базе. Поддерживаемая запись сначала добавляется в хранимое backend
состояние калькулятора и только затем отмечается в журнале донатов как обработанная.
Если процесс прервётся между этими действиями, следующая сверка завершит обработку
без дубликата. Открытая страница для импорта не требуется.

Импортированный донат содержит:

- исходный никнейм;
- исходную сумму и валюту;
- время доната, показанное по Москве;
- уникальный ID DonationAlerts, используемый для защиты от дубликатов;
- состояние Chat, установленное в момент получения backend.

Поддерживаются `RUB`, `BRL`, `BYN`, `EUR`, `KZT`, `PLN`, `TRY`, `UAH`, `USD` и `UZS`. Если
DonationAlerts когда-либо вернёт неизвестную валюту, такой донат останется в backend
в ожидании, а интерфейс сообщит, какая валюта не поддержана.

### Авто-Chat для новых донатов

Переключатель **Chat all** рядом с суммой раунда управляет только теми донатами, которые
backend получит после переключения:

- выключен — новый донат учитывается под исходным никнеймом;
- включён — исходный никнейм сохраняется, но при расчёте вклад относится к общему
  участнику `Chat`.

Состояние режима сохраняется в backend и остаётся после перезапуска. Изменение режима
не переписывает ранее полученные донаты. У каждой активной записи Chat всё равно можно
включить или выключить вручную.

#### Управление Авто-Chat через curl

Пока локальное приложение запущено, переключить текущее состояние Авто-Chat можно
из PowerShell командой:

```powershell
curl.exe --request POST "http://127.0.0.1:5741/api/settings/auto-chat/toggle"
```

Тело запроса не требуется. Backend вернёт новое состояние:

```json
{"enabled":true}
```

или:

```json
{"enabled":false}
```

Каждый повторный `POST` меняет значение на противоположное. Чтобы сначала узнать
текущее состояние, выполните:

```powershell
curl.exe "http://127.0.0.1:5741/api/settings/auto-chat"
```

Если нужно установить известное значение независимо от текущего состояния, используйте
`PUT`. Включение:

```powershell
'{"enabled":true}' | curl.exe --request PUT --header "Content-Type: application/json" --data-binary "@-" "http://127.0.0.1:5741/api/settings/auto-chat"
```

Выключение:

```powershell
'{"enabled":false}' | curl.exe --request PUT --header "Content-Type: application/json" --data-binary "@-" "http://127.0.0.1:5741/api/settings/auto-chat"
```

Используйте именно `curl.exe`, потому что в Windows PowerShell имя `curl` может быть
псевдонимом другой команды. Если Gambalator запущен на другом порту, замените `5741`
во всех адресах. Интерфейс получит новое состояние от backend при следующем обновлении
статуса, обычно в течение пяти секунд.

### Отключение и повторная авторизация

Кнопка **ОТКЛЮЧИТЬ** останавливает автоматическую синхронизацию и удаляет OAuth-токены,
но сохраняет App ID и API Key. После этого поле API Key показывает маску, чтобы было
понятно, что ключ сохранён. Для подключения можно оставить это поле пустым и повторно
использовать сохранённый ключ.

Истёкший access token обновляется автоматически. Если refresh token тоже больше не
принимается, появится блок **Требуется повторная авторизация**. Нажмите
**ПЕРЕПОДКЛЮЧИТЬ DONATIONALERTS** — повторно вводить App ID и API Key не потребуется.

## 3. Загрузка истории DonationAlerts

Эта функция загружает из DonationAlerts донаты, которые были отправлены ещё до
первого запуска Gambalator. Она также возвращает известные локальной базе записи,
которые были удалены из калькулятора.

1. Нажмите зелёную кнопку **DonationAlerts** в шапке.
2. В секции **Загрузка истории** выберите начальный момент:

   - **10 МИН** — ровно десять минут назад;
   - **1 ЧАС** — ровно один час назад;
   - **СЕГОДНЯ** — сегодня с `00:00` по Москве;
   - **3 ДНЯ** — ровно три дня назад;
   - **5 ДНЕЙ** — ровно пять дней назад;
   - либо выберите дату в тёмном календаре и введите время вручную.

3. Время вводится в 24-часовом формате `ЧЧ:ММ` и трактуется как московское.
4. Нажмите **ЗАГРУЗИТЬ ИСТОРИЮ**. Gambalator постранично проверит DonationAlerts;
   при большой истории это может занять время.
5. Проверьте в окне подтверждения общее количество доступных для добавления донатов,
   число впервые сохранённых архивных записей и число пропущенных неподдерживаемых
   валют.
6. Подтвердите действие.

После успешной проверки секция показывает строку **История уже проверена с ...** с
самой ранней достигнутой датой по Москве.

Повторная загрузка не создаёт дубль доната, пока строка с тем же DonationAlerts ID
остаётся активной. Использованные строки в **ИСТОРИЯ** и история победителей намеренно
не блокируют добавление: рассчитанный или вручную удалённый донат из выбранного периода
можно снова получить целиком и разыграть заново. Старые использованные строки и прежние
победители при этом автоматически не удаляются.

Поэтому перед полным перерасчётом сначала очистите нужные записи и историю победителей,
а затем загрузите выбранный период. Если сначала загрузить три дня, оставить эти донаты
активными и затем выбрать пять дней, Gambalator добавит только недостающие более старые
донаты. Если донаты первых трёх дней уже рассчитаны или удалены, явная загрузка пяти
дней добавит их снова — это ожидаемое поведение. API DonationAlerts не умеет начинать
запрос сразу с произвольной даты, поэтому backend всё равно проходит новые страницы,
пока не достигнет выбранного времени.

Перед окном подтверждения новые ID сохраняются в SQLite как архивные и ещё не влияют
на активную сумму. После подтверждения найденные донаты автоматически занимают своё
исходное хронологическое место в очереди и получают новый внутренний ID; исходный
DonationAlerts ID сохраняется для проверки происхождения. Если закрыть окно
подтверждения, новые записи останутся в архиве и снова появятся в следующем
предварительном просмотре.

Сохранённая позиция обычной синхронизации DonationAlerts не откатывается: самая ранняя
успешно проверенная дата хранится отдельно. Впервые найденная история всегда
добавляется как обычные донаты без Chat; отдельной настройки «импортировать историю
как Chat» нет. Ранее известные записи сохраняют свою метку Chat. История победителей
и использованные строки не изменяются. Сообщение о завершённой загрузке скрывается
через пять секунд.

Если API завершился ошибкой или backend не успел дойти до выбранной даты в пределах
допустимого числа страниц, частично просмотренные записи и новая граница истории не
сохраняются. Можно устранить проблему и безопасно повторить действие.

## 4. Добавление доната вручную

Нажмите кнопку `+` в правой части строки с кнопками расчёта. Форма **Добавить донат
вручную** откроется в отдельном окне.

Заполните поля:

1. **Никнейм** — непустое имя участника.
2. **Сумма** — положительное число максимум с одним знаком после запятой. Можно
   использовать точку или запятую, например `1250.5` или `1250,5`.
3. **Валюта** — `RUB`, `BRL`, `BYN`, `EUR`, `KZT`, `PLN`, `TRY`, `UAH`, `USD` или `UZS`;
   по умолчанию выбрана `RUB`.
4. **Chat** — золотой переключатель, который по умолчанию выключен.

Нажмите **ДОБАВИТЬ** или клавишу `Enter`. После успешного добавления форма остаётся
открытой, очищает никнейм и сумму, возвращает валюту `RUB`, выключает Chat и снова
переводит курсор в поле никнейма. Это позволяет быстро вводить несколько записей
подряд.

Если Chat включён, исходный никнейм остаётся видимым, но вклад при расчёте объединяется
с другими отмеченными донатами под именем `Chat`. Такие строки имеют золотую
подсветку.

## 5. Активные записи

Активные записи ещё не были полностью использованы для завершённых гамбашаров.
По центру заголовка показаны жёлтая общая сумма в RUB с учётом применимых курсов,
серый разделитель и розовое количество полных гамбашаров, которые уже можно рассчитать, например
`10000.0 RUB | 2 гамбашара`.

### Порядок и нумерация

По умолчанию список показан от старых донатов к новым: первая запись находится сверху,
а номера возрастают сверху вниз, например `1, 2, 3, 4`. В таком же каноническом порядке
донаты участвуют в расчёте, если оператор не переставил их вручную.

Порядок можно изменить перетаскиванием строки за значок с точками. Ручное изменение
порядка влияет и на последовательность будущего расчёта.

Кнопка с иконкой `⇅` меняет только порядок отображения. Подсказка при наведении
показывает, какой порядок будет включён. Кнопка не переставляет очередь и не влияет
на последовательность расчёта.

Оранжевая рамка отмечает донаты, которые полностью или частично попадут в ближайший
полный гамбашар. Донат, на котором достигается сумма раунда, тоже отмечен. Если суммы
для полного гамбашара пока недостаточно, рамки нет. Переключение порядка отображения
не меняет эту отметку.

### Визуальное объединение донатов

Кнопка **Объединить** включает выбор строк. Отметьте минимум два соседних доната и
нажмите **Объединить выбранные**. Никнеймы могут отличаться, но все выбранные строки
должны быть либо обычными, либо отмеченными Chat. Смешивать обычные и Chat-донаты в
одной группе нельзя. Название обычной группы заранее заполняется никнеймом первого
выбранного доната, но его можно изменить. Для Chat-группы автоматически используется
название `Chat`.

Группа выглядит как обычная строка: имеет один номер, ручку перетаскивания, общую
сумму в RUB и компактные кнопки действий. Нажмите на название или стрелку, чтобы
раскрыть её и увидеть все исходные донаты с их номерами, никнеймами, суммами и
состоянием Chat. Название обычной группы можно отредактировать. Перетаскивание группы
перемещает все входящие в неё донаты единым блоком и меняет их порядок расчёта.
Отдельной розовой подсветки у группы нет. Если хотя бы один участник попадёт в
ближайший гамбашар, рамка показывается на свёрнутой группе; после раскрытия она
остаётся только у тех исходных донатов, которые действительно будут использованы.

Кнопка **Авто: выкл / Авто: вкл** включает автоматическое объединение. Оно собирает
каждую непрерывную последовательность донатов с одинаковым никнеймом, а также каждую
непрерывную последовательность Chat-донатов. Если между двумя подходящими донатами
есть другая запись, через этот разрыв они не объединяются.

После выключения **Авто** уже созданные группы остаются объединёнными. Выключение
только прекращает автоматическое создание и расширение групп для следующих донатов.
Их можно раскрыть или разъединить вручную в любое время.

Состояние **Авто**, созданные группы, их названия и выполненные вручную разъединения
сохраняются в браузере. После перезагрузки страницы они восстанавливаются и
проверяются по текущим активным донатам; уже рассчитанные или удалённые строки не
возвращаются в группу.

Компактное действие разъединения возвращает исходные строки выбранной группы. Удаление
группы удаляет все входящие в неё активные донаты. Само объединение, раскрытие и
переименование не меняют исходные суммы или расчёт; только явное перетаскивание либо
удаление выполняет соответствующее действие над всеми участниками группы.

### Информация в строке

Строка активного доната показывает:

- номер и никнейм;
- сумму и валюту;
- рублёвый эквивалент для иностранной валюты;
- исходную сумму и валюту отдельной строкой, если донат был разделён;
- московское время для доната, импортированного из DonationAlerts;
- золотой переключатель Chat;
- кнопки редактирования и удаления.

### Редактирование

Нажмите кнопку с карандашом, чтобы изменить никнейм, сумму, валюту или Chat. Кнопка
`✓` сохраняет изменения, кнопка `×` рядом отменяет редактирование.

При изменении никнейма или Chat сохраняются ссылка на исходный DonationAlerts-донат и
данные исходной суммы разделённого доната. Если изменить сумму или валюту активного
остатка, устаревший фиксированный рублёвый эквивалент удаляется и рассчитывается заново.

Chat можно переключить прямо в обычной строке, не открывая режим редактирования.
Кнопка `×` в правой части обычной строки запрашивает подтверждение перед удалением
активной записи. Такое же подтверждение появляется при удалении визуальной группы.

Удалённый импортированный донат не появляется снова при обычной синхронизации, потому
что backend уже считает его учтённым. Если он нужен снова, используйте **Загрузку
истории** и выберите дату до времени этого доната. Если от него осталась использованная
часть, она не помешает восстановить полный исходный донат.

## 6. Параметры расчёта и валюты

Нажмите **Меню** в шапке и выберите **Параметры расчёта**. Настройки сразу откроются
в отдельном прокручиваемом окне; дополнительного свёрнутого блока внизу страницы нет.
Закройте окно кнопкой `×`, нажатием на затемнённую область или клавишей `Escape`.

### Сумма гамбашара

По умолчанию один гамбашар равен `5000.0 RUB`. Чтобы изменить значение:

1. Введите новую положительную сумму максимум с одним знаком после запятой.
2. Нажмите **Обновить**.

### Курсы валют

Курс означает стоимость указанного количества валюты в рублях. Значения по умолчанию:

| Валюта | Курс |
|---|---:|
| EUR | `1 EUR = 100.0 RUB` |
| USD | `1 USD = 85.5 RUB` |
| BYN | `1 BYN = 28.2 RUB` |
| KZT | `100 KZT = 19.0 RUB` |
| UAH | `10 UAH = 19.4 RUB` |
| BRL | `1 BRL = 17.0 RUB` |
| TRY | `10 TRY = 17.9 RUB` |
| PLN | `1 PLN = 23.2 RUB` |
| UZS | `10000 UZS = 73.1 RUB` |

EUR и USD видны сразу. Нажмите **ОТКРЫТЬ ВСЕ ВАЛЮТЫ**, чтобы изменить остальные.
После редактирования нажмите **Сохранить курсы**.

Чтобы заполнить все курсы автоматически, нажмите **Получить курсы ЦБ РФ**. Backend
загрузит последние официальные курсы Банка России и округлит их до одного знака после
запятой, который поддерживает Gambalator. Загруженные значения сначала появляются в
полях редактирования: проверьте дату курса и нажмите **Сохранить курсы**, чтобы начать
использовать их в расчётах. Для загрузки нужен доступ к `www.cbr.ru`; API-ключ не нужен.

Импорт донатов не ждёт загрузки курсов. Если Банк России недоступен, приложение
продолжает работать с последними сохранёнными значениями. Для обновления используйте
кнопку **Получить курсы ЦБ РФ**, затем явно сохраните загруженные курсы.

Пока в настройках есть несохранённые изменения, рядом отображается пометка
**Не сохранено**, а кнопки расчёта отключены. Сначала сохраните сумму раунда и курсы.

Для активного доната в иностранной валюте используется курс, сохранённый на момент
запуска расчёта. После использования доната его рублёвая сумма и применённый
курс фиксируются: более позднее изменение курса не переписывает историю.

## 7. Расчёт гамбашаров

Нажмите **Рассчитать все**, чтобы обработать все доступные полные раунды, либо
**Рассчитать один**, чтобы завершить только один полный гамбашар. При совместном
запуске отдельный listener Only_DA-Goal обрабатывает F6 для одного раунда и F7 для
всех доступных полных раундов даже при закрытой странице Gambalator. Старые привязки
F20, F21 и F22 продолжают работать по исходной логике Only_DA-Goal.

Приложение:

1. переводит активные суммы в рубли;
2. обрабатывает записи в порядке расчёта;
3. автоматически завершает все полные гамбашары;
4. выбирает Chat или обычный режим по донату, закрывшему каждый гамбашар;
5. переносит использованные части в **ИСТОРИЯ**;
6. добавляет победителей в **История победителей**;
7. оставляет незавершённый остаток активным.

Если общей суммы недостаточно даже для одного гамбашара, записи не изменяются, а
сообщение показывает, сколько рублей не хватает.

### Как выбирается победитель

- Режим выбора определяет донат, чья часть закрыла гамбашар.
- Если этот донат отмечен `Chat`, победителем становится `Chat`. В истории показывается
  сумма всех отмеченных Chat-частей данного гамбашара.
- Если закрывающий донат обычный, все отмеченные Chat-части исключаются из выбора.
  Победитель определяется только среди обычных донатов.
- Обычные части одного никнейма складываются. Регистр и пробелы по краям не
  различаются: `Chel_1`, `chel_1` и ` CHEL_1 ` считаются одним участником.
- При равенстве максимальных обычных сумм показываются все победители через запятую.
- Для большого доната, пересекающего несколько границ, режим определяется отдельно в
  каждом гамбашаре.
- Один участник может победить в нескольких гамбашарах.
- Победители, уже сохранённые до обновления, автоматически не пересчитываются.

### Разделение большого доната

Если один донат пересекает границу гамбашара, нужная часть завершает текущий
гамбашар, а остаток переходит дальше.

Пример при сумме гамбашара `5000.0 RUB`:

1. `Chel_1 — 4000.0 RUB`;
2. `Chel_2 — 2000.0 RUB`.

Из второго доната `1000.0 RUB` завершает первый гамбашар, а оставшиеся `1000.0 RUB`
остаются активными для следующего. Победитель завершённого гамбашара — `Chel_1` с
вкладом `4000.0 RUB`.

На каждой созданной части показывается `Исходный донат: 2000.0 RUB`. Для иностранной
валюты подробная строка с применённым курсом также сохраняется в **ИСТОРИЯ**.

Подробные правила и дополнительные примеры находятся в
[CALCULATION_LOGIC_RU.md](./CALCULATION_LOGIC_RU.md).

## 8. История розыгрышей и победителей

Строка расположена над рабочей областью. По центру показываются имя последнего
победителя, разделитель `|` и победившая сумма в RUB. Нажатие на любую часть строки
сразу открывает прокручиваемое окно истории; режима раскрытия внутри страницы нет.

Для каждого завершённого гамбашара показываются:

- подзаголовок `Гамбашар N`;
- никнейм победителя или список победителей при ничьей;
- победившая сумма в рублях.

По умолчанию виден только результат. Нажмите строку гамбашара, чтобы развернуть под
ней все использованные донаты этого раунда; повторное нажатие сворачивает участников.
Никнейм победителя среди участников выделен. Chat-донаты сохраняют исходные никнеймы,
золотую подсветку и метку `Chat`, а части разделённого доната показывают исходную сумму
и валюту всего доната.

Никнейм победителя и сумма расположены рядом в одной строке по центру карточки окна.

Новые результаты находятся сверху. После очередного расчёта более старые победители
становятся бледнее, поэтому свежие результаты заметнее.

В широком всплывающем окне длинные никнеймы и списки победителей переносятся на новые
строки и отображаются полностью. Окно закрывается кнопкой `×`, клавишей `Escape` или
нажатием на затемнённую область.

Кнопка **Очистить историю** находится внутри окна и удаляет результаты завершённых
раундов вместе со списками их участников. Активные донаты, курсы и сумма гамбашара
сохраняются. После полной очистки истории нумерация новых раундов начинается с 1.

## 9. Кнопки очистки

Действия, удаляющие данные, требуют подтверждения в тёмном всплывающем окне.

| Действие | Удаляется | Сохраняется |
|---|---|---|
| **Удалить активные донаты** | только активные донаты | вся история розыгрышей, настройки |
| **Очистить историю** | результаты завершённых раундов и их участники | активные донаты, настройки |

Удаление записи из калькулятора не удаляет исходный донат из локального журнала
DonationAlerts. При необходимости его можно вернуть через **Загрузку истории**.

## 10. Сохранение данных

Локальный backend автоматически сохраняет после каждого изменения:

- сумму гамбашара и курсы валют;
- активные и использованные записи;
- порядок записей и состояния Chat;
- историю победителей.

Ручные записи сохраняются только внутри строки `calculator_state`; они не копируются
в таблицу `donations`. Таблица `donations` — отдельный журнал записей, полученных из
DonationAlerts. Поэтому удаление ручной записи нельзя отменить загрузкой истории.

Эти данные вместе с базой DonationAlerts и курсором синхронизации находятся в:

```text
%LOCALAPPDATA%\Gambalator
```

Основной файл — `gambalator.sqlite3`. Это бинарная база SQLite, поэтому обычный
текстовый редактор покажет нечитаемые символы. Для просмотра без изменения используйте
DB Browser for SQLite или командную программу `sqlite3`. Основные таблицы:

- `calculator_state` — одна JSON-строка с настройками, активными и использованными
  записями и историей победителей;
- `donations` — журнал DonationAlerts со статусами `pending` и `acknowledged`;
- `sync_state` — курсоры синхронизации, Авто-Chat и самая ранняя проверенная дата
  истории.

Перед ручным редактированием остановите Gambalator и сохраните резервную копию файла.

Standalone-версия `dist-single/index.html` и статическая версия на GitHub Pages не
используют backend: их ручное состояние хранится отдельно в `localStorage` текущего
профиля браузера. Автоматического переноса между `localStorage` и SQLite нет.

Поэтому новая папка с обновлённой версией программы на том же компьютере продолжает
работу с прежней базой. Полное описание установки и обновления находится в
[WINDOWS_INSTALL_RU.md](./WINDOWS_INSTALL_RU.md).

## 11. Настройка цветов и толщины шрифта

Все настраиваемые цвета собраны в самом начале файла `src/styles.css`, внутри блока
**EASY THEME SETTINGS**. Для изменения темы не нужно разбираться в остальных CSS-правилах:

1. Откройте `src/styles.css` обычным текстовым редактором.
2. Меняйте только значения в начале файла после двоеточия, например
   `--color-pink: #fa75db;`.
3. Чтобы найти конкретную кнопку, используйте поиск по её видимому названию. Рядом с
   переменными есть комментарии `“DonationAlerts”`, `“Рассчитать все”`,
   `“Сохранить курсы”`, `“Объединить”` и другие.
4. Пересоберите приложение командой `mise run build` или перезапустите обычный
   локальный запуск, который выполняет сборку.

Основные переменные `--color-*` меняют палитру сразу во всех компонентах. Переменные
`--button-*` позволяют отдельно переопределить конкретные кнопки. Например, вместо
ссылки на общий цвет можно указать собственный HEX-код:

```css
--button-calculate-all-color: #00bfff;
```

Цвет рамки донатов ближайшего гамбашара задаётся через
`--next-round-border-color`. Цвета победителей, активной суммы и количества доступных
гамбашаров также имеют подписанные переменные в этом блоке.

Толщина всего текста управляется одной строкой:

```css
--font-weight-all: 500;
```

Значение `500` соответствует текущему виду заголовка **АКТИВНЫЕ ЗАПИСИ** и применяется
ко всему тексту проекта.

## 12. Рекомендуемый рабочий процесс

1. Запустите `start-gambalator.cmd` и не закрывайте терминал. При интеграции с
   Only_DA-Goal вместо этого запускайте `Only_DA-Goal\1.bat`.
2. Откройте `http://127.0.0.1:5741`.
3. Проверьте зелёные соединения с локальным сервером и DonationAlerts.
4. При необходимости включите **Chat all** в шапке.
5. Откройте **Меню** → **Параметры расчёта** и проверьте сумму гамбашара и курсы валют.
6. Дождитесь автоматических донатов или добавьте записи вручную.
7. Проверьте никнеймы, суммы, Chat и порядок активных записей.
8. Нажмите **Рассчитать все** или **Рассчитать один**.
9. Посмотрите свежие результаты в истории победителей.
10. При необходимости откройте **Меню** → **История** или очистите историю розыгрышей.
11. По завершении работы остановите сервер клавишами `Ctrl+C`.
