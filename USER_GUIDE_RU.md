# Руководство пользователя Gambalator

Gambalator собирает донаты в упорядоченную очередь, переводит их в рубли, делит на
гамбашары фиксированной суммы и определяет участника с наибольшим вкладом в каждом
завершённом гамбашаре. Интерфейс рассчитан на работу на компьютере и отображается на
русском языке.

## 1. Открытие приложения

Запустите локальное приложение и откройте:

```text
http://127.0.0.1:5741
```

В верхней части страницы показана краткая сводка:

- текущая сумма одного гамбашара;
- количество активных записей;
- количество завершённых гамбашаров в истории победителей.

Основные блоки страницы расположены в следующем порядке:

1. подключение **DonationAlerts**;
2. форма ручного добавления доната;
3. активные записи, кнопки управления и история использованных записей;
4. история победителей;
5. параметры расчёта.

Сворачиваемые блоки можно раскрывать нажатием на их заголовок.

## 2. Подключение DonationAlerts

В свернутом блоке **DonationAlerts** виден общий статус и схема:

```text
Веб-страница → Локальный сервер → DonationAlerts
```

Каждое соединение проверяется отдельно:

- **Связь есть** означает, что страница получает ответы от локального Python-сервера;
- **Синхронизация активна** означает, что backend подключён к DonationAlerts и
  опрашивает его API;
- зелёные подписи и точки обозначают исправное соединение;
- красная подпись сообщает об ошибке или необходимости авторизации.

### Первое подключение

1. Разверните блок **DonationAlerts**.
2. Зарегистрируйте приложение в DonationAlerts с Redirect URI, показанным на странице.
3. Введите его **App ID** и **API Key**.
4. Нажмите **ПОДКЛЮЧИТЬ DONATIONALERTS**.
5. Подтвердите доступ на сайте DonationAlerts.
6. После возврата проверьте зелёные состояния соединений.

После подключения видны количество донатов, ожидающих импорта, время последней
синхронизации по Москве и тип хранилища авторизации. Сообщение об успешном подключении
скрывается автоматически через пять секунд.

При первом подключении приложение создаёт начальную точку на текущем последнем донате
и не импортирует всю старую историю аккаунта. Донаты, отправленные после подключения,
появляются в активном списке через несколько секунд. Backend и страница используют
отдельные пятисекундные циклы проверки, поэтому в редком случае ожидание может занять
примерно до десяти секунд.

### Автоматический импорт

Backend проверяет DonationAlerts каждые пять секунд и сохраняет новые донаты в
локальной SQLite-базе. Страница также каждые пять секунд проверяет очередь backend.
Поддерживаемая запись сначала сохраняется во frontend, а только затем отмечается в
backend как учтённая. Повторные запросы не создают дубликаты.

Импортированный донат содержит:

- исходный никнейм;
- исходную сумму и валюту;
- время доната, показанное по Москве;
- уникальный ID DonationAlerts, используемый для защиты от дубликатов;
- состояние Chat, установленное в момент получения backend.

Поддерживаются `RUB`, `USD`, `EUR`, `BYN`, `KZT`, `UAH`, `BRL` и `TRY`. Если
DonationAlerts когда-либо вернёт неизвестную валюту, такой донат останется в backend
в ожидании, а интерфейс сообщит, какая валюта не поддержана.

### Авто-Chat для новых донатов

Переключатель **Авто-Chat для новых донатов** управляет только теми донатами, которые
backend получит после переключения:

- выключен — новый донат учитывается под исходным никнеймом;
- включён — исходный никнейм сохраняется, но при расчёте вклад относится к общему
  участнику `Chat`.

Состояние режима сохраняется в backend и остаётся после перезапуска. Изменение режима
не переписывает ранее полученные донаты. У каждой активной записи Chat всё равно можно
включить или выключить вручную.

#### Управление Авто-Chat через curl

Пока локальное приложение запущено, переключить текущее состояние Авто-Chat можно
из PowerShell командой:

```powershell
curl.exe --request POST "http://127.0.0.1:5741/api/settings/auto-chat/toggle"
```

Тело запроса не требуется. Backend вернёт новое состояние:

```json
{"enabled":true}
```

или:

```json
{"enabled":false}
```

Каждый повторный `POST` меняет значение на противоположное. Чтобы сначала узнать
текущее состояние, выполните:

```powershell
curl.exe "http://127.0.0.1:5741/api/settings/auto-chat"
```

Если нужно установить известное значение независимо от текущего состояния, используйте
`PUT`. Включение:

```powershell
'{"enabled":true}' | curl.exe --request PUT --header "Content-Type: application/json" --data-binary "@-" "http://127.0.0.1:5741/api/settings/auto-chat"
```

Выключение:

```powershell
'{"enabled":false}' | curl.exe --request PUT --header "Content-Type: application/json" --data-binary "@-" "http://127.0.0.1:5741/api/settings/auto-chat"
```

Используйте именно `curl.exe`, потому что в Windows PowerShell имя `curl` может быть
псевдонимом другой команды. Если Gambalator запущен на другом порту, замените `5741`
во всех адресах. Интерфейс получит новое состояние от backend при следующем обновлении
статуса, обычно в течение пяти секунд.

### Отключение и повторная авторизация

Кнопка **ОТКЛЮЧИТЬ** останавливает автоматическую синхронизацию и удаляет OAuth-токены,
но сохраняет App ID и API Key. После этого поле API Key показывает маску, чтобы было
понятно, что ключ сохранён. Для подключения можно оставить это поле пустым и повторно
использовать сохранённый ключ.

Истёкший access token обновляется автоматически. Если refresh token тоже больше не
принимается, появится блок **Требуется повторная авторизация**. Нажмите
**ПЕРЕПОДКЛЮЧИТЬ DONATIONALERTS** — повторно вводить App ID и API Key не потребуется.

## 3. Повторный импорт удалённых донатов

Повторный импорт возвращает записи DonationAlerts, которые уже были получены backend,
импортированы в браузер, а затем удалены из списка. Он не загружает произвольную
старую историю, которой никогда не было в локальной базе.

1. Разверните подключённый блок **DonationAlerts**.
2. В секции **Повторный импорт** выберите начальный момент:

   - **10 МИН** — ровно десять минут назад;
   - **1 ЧАС** — ровно один час назад;
   - **СЕГОДНЯ** — сегодня с `00:00` по Москве;
   - **3 ДНЯ** — ровно три дня назад;
   - **5 ДНЕЙ** — ровно пять дней назад;
   - либо выберите дату в тёмном календаре и введите время вручную.

3. Время вводится в 24-часовом формате `ЧЧ:ММ` и трактуется как московское.
4. Нажмите **ПЕРЕИМПОРТИРОВАТЬ**.
5. Проверьте количество найденных донатов в окне подтверждения.
6. Подтвердите действие.

Записи, которые уже присутствуют среди активных или использованных, не считаются и
не дублируются. Восстановленные донаты появляются автоматически и занимают своё
первоначальное хронологическое место в очереди расчёта. Сохранённая позиция
синхронизации DonationAlerts не откатывается, состояние Chat сохраняется, а история
победителей не изменяется. Сообщение о подготовленном импорте скрывается через пять
секунд.

## 4. Добавление доната вручную

Блок **Добавить донат вручную** по умолчанию свёрнут. Нажмите на заголовок, чтобы
открыть форму.

Заполните поля:

1. **Никнейм** — непустое имя участника.
2. **Сумма** — положительное число максимум с одним знаком после запятой. Можно
   использовать точку или запятую, например `1250.5` или `1250,5`.
3. **Валюта** — `RUB`, `USD`, `EUR`, `BYN`, `KZT`, `UAH`, `BRL` или `TRY`;
   по умолчанию выбрана `RUB`.
4. **Chat** — золотой переключатель, который по умолчанию выключен.

Нажмите **ДОБАВИТЬ** или клавишу `Enter`. После успешного добавления форма остаётся
открытой, очищает никнейм и сумму, возвращает валюту `RUB`, выключает Chat и снова
переводит курсор в поле никнейма. Это позволяет быстро вводить несколько записей
подряд.

Если Chat включён, исходный никнейм остаётся видимым, но вклад при расчёте объединяется
с другими отмеченными донатами под именем `Chat`. Такие строки имеют золотую
подсветку.

## 5. Активные записи

Активные записи ещё не были полностью использованы для завершённых гамбашаров.

### Порядок и нумерация

На странице список показан в обратном порядке: последний добавленный донат находится
сверху. Номера также убывают сверху вниз, например `4, 3, 2, 1`.

Расчёт при этом по умолчанию идёт в настоящем порядке добавления: сначала запись `1`,
затем `2`, `3` и `4`. Обратное отображение сделано только для удобства, чтобы новый
донат сразу был виден сверху.

Порядок можно изменить перетаскиванием строки за значок с точками. Ручное изменение
порядка влияет и на последовательность будущего расчёта.

### Информация в строке

Строка активного доната показывает:

- номер и никнейм;
- сумму и валюту;
- рублёвый эквивалент для иностранной валюты;
- московское время для доната, импортированного из DonationAlerts;
- золотой переключатель Chat;
- кнопки редактирования и удаления.

### Редактирование

Нажмите кнопку с карандашом, чтобы изменить никнейм, сумму, валюту или Chat. Кнопка
`✓` сохраняет изменения, кнопка `×` рядом отменяет редактирование.

Chat можно переключить прямо в обычной строке, не открывая режим редактирования.
Кнопка `×` в правой части обычной строки удаляет активную запись.

Удалённый импортированный донат не появляется снова при обычной синхронизации, потому
что backend уже считает его учтённым. Если он нужен снова, используйте **Повторный
импорт**.

## 6. Параметры расчёта и валюты

Блок **Параметры расчёта** находится внизу страницы и по умолчанию свёрнут. В строке
заголовка показаны текущая сумма гамбашара и основные курсы EUR и USD.

### Сумма гамбашара

По умолчанию один гамбашар равен `5000.0 RUB`. Чтобы изменить значение:

1. Введите новую положительную сумму максимум с одним знаком после запятой.
2. Нажмите **Обновить**.

### Курсы валют

Курс означает стоимость указанного количества валюты в рублях. Значения по умолчанию:

| Валюта | Курс |
|---|---:|
| EUR | `1 EUR = 100.0 RUB` |
| USD | `1 USD = 85.5 RUB` |
| BYN | `1 BYN = 28.2 RUB` |
| KZT | `100 KZT = 19.0 RUB` |
| UAH | `10 UAH = 19.4 RUB` |
| BRL | `1 BRL = 17.0 RUB` |
| TRY | `10 TRY = 17.9 RUB` |

EUR и USD видны сразу. Нажмите **ОТКРЫТЬ ВСЕ ВАЛЮТЫ**, чтобы изменить остальные.
После редактирования нажмите **Сохранить курсы**.

Пока в настройках есть несохранённые изменения, рядом отображается пометка
**Не сохранено**, а кнопка **РАССЧИТАТЬ** отключена. Сначала сохраните сумму раунда и
курсы.

Для активного доната в иностранной валюте используется курс, сохранённый на момент
нажатия **РАССЧИТАТЬ**. После использования доната его рублёвая сумма и применённый
курс фиксируются: более позднее изменение курса не переписывает историю.

## 7. Расчёт гамбашаров

Нажмите **РАССЧИТАТЬ**, когда активная очередь готова.

Приложение:

1. переводит активные суммы в рубли;
2. обрабатывает записи в порядке расчёта;
3. автоматически завершает все полные гамбашары;
4. определяет наибольший суммарный вклад в каждом гамбашаре;
5. переносит использованные части в **ИСТОРИЯ**;
6. добавляет победителей в **История победителей**;
7. оставляет незавершённый остаток активным.

Если общей суммы недостаточно даже для одного гамбашара, записи не изменяются, а
сообщение показывает, сколько рублей не хватает.

### Как выбирается победитель

- Внутри одного гамбашара все части донатов одного никнейма складываются.
- Регистр и пробелы по краям не различаются: `Chel_1`, `chel_1` и ` CHEL_1 ` считаются
  одним участником.
- Побеждает участник с максимальной суммой в этом гамбашаре.
- При равенстве максимальных сумм показываются все победители через запятую.
- Все донаты с включённым Chat складываются под общим именем `Chat`.
- Один участник может победить в нескольких гамбашарах.

### Разделение большого доната

Если один донат пересекает границу гамбашара, нужная часть завершает текущий
гамбашар, а остаток переходит дальше.

Пример при сумме гамбашара `5000.0 RUB`:

1. `Chel_1 — 4000.0 RUB`;
2. `Chel_2 — 2000.0 RUB`.

Из второго доната `1000.0 RUB` завершает первый гамбашар, а оставшиеся `1000.0 RUB`
остаются активными для следующего. Победитель завершённого гамбашара — `Chel_1` с
вкладом `4000.0 RUB`.

Подробные правила и дополнительные примеры находятся в
[CALCULATION_LOGIC_RU.md](./CALCULATION_LOGIC_RU.md).

## 8. ИСТОРИЯ использованных записей

Блок **ИСТОРИЯ** расположен под кнопками управления и по умолчанию свёрнут. Его
счётчик показывает количество групп-гамбашаров, а не количество отдельных строк.

После раскрытия:

- группы расположены от нового гамбашара к старому;
- заголовок `Гамбашар N` отделяет один гамбашар от другого;
- внутри группы строки разделены тонкими линиями;
- никнейм победителя выделен;
- Chat-донат сохраняет исходный никнейм, золотую подсветку и метку `Chat`;
- использованные записи показаны более бледным цветом;
- части разделённого доната находятся в соответствующих гамбашарах.

Кнопка **Удалить использованные** удаляет только эти строки. Активная очередь,
история победителей и настройки сохраняются.

## 9. История победителей

Для каждого завершённого гамбашара показываются:

- подзаголовок `Гамбашар N`;
- никнейм победителя или список победителей при ничьей;
- победившая сумма в рублях.

Новые результаты находятся сверху. После очередного расчёта более старые победители
становятся бледнее, поэтому свежие результаты заметнее.

Кнопка с иконкой разворачивания открывает широкое всплывающее окно. В нём длинные
никнеймы и списки победителей переносятся на новые строки и отображаются полностью.
Окно закрывается кнопкой `×`, клавишей `Escape` или нажатием на затемнённую область.

Кнопка **Очистить историю** удаляет только список победителей. Активные и
использованные записи, курсы и сумма гамбашара остаются.

Нумерация продолжается после максимального номера, оставшегося либо в истории
победителей, либо в **ИСТОРИЯ**. Поэтому очистка только истории победителей не
обязательно начинает нумерацию с 1. Она начнётся заново, только когда обе истории
пусты.

## 10. Кнопки очистки

Действия, удаляющие данные, требуют подтверждения в тёмном всплывающем окне.

| Действие | Удаляется | Сохраняется |
|---|---|---|
| **Удалить использованные** | использованные строки в `ИСТОРИЯ` | активные записи, победители, настройки |
| **Очистить все записи** | активные и использованные записи | победители, настройки |
| **Очистить историю** | история победителей | все записи, настройки |

Удаление записи из браузера не удаляет соответствующий донат из локальной базы
DonationAlerts. При необходимости его можно вернуть повторным импортом.

## 11. Сохранение данных

Frontend автоматически сохраняет после каждого изменения:

- сумму гамбашара и курсы валют;
- активные и использованные записи;
- порядок записей и состояния Chat;
- историю победителей.

Эти данные находятся в `localStorage` браузера для адреса
`http://127.0.0.1:5741`. Они сохраняются после обновления страницы и перезапуска
приложения, если используются тот же браузер, тот же профиль, адрес и порт.

Другой браузер, профиль инкогнито, адрес `localhost`, другой порт или очистка данных
сайта создадут отдельное пустое frontend-хранилище.

Backend отдельно хранит локальную базу DonationAlerts и курсор синхронизации в:

```text
%LOCALAPPDATA%\Gambalator
```

Поэтому новая папка с обновлённой версией программы на том же компьютере продолжает
работу с прежней базой. Полное описание установки и обновления находится в
[WINDOWS_INSTALL_RU.md](./WINDOWS_INSTALL_RU.md).

## 12. Рекомендуемый рабочий процесс

1. Запустите `start-gambalator.cmd` и не закрывайте терминал.
2. Откройте `http://127.0.0.1:5741`.
3. Проверьте зелёные соединения с локальным сервером и DonationAlerts.
4. При необходимости включите **Авто-Chat для новых донатов**.
5. Проверьте сумму гамбашара и курсы валют.
6. Дождитесь автоматических донатов или добавьте записи вручную.
